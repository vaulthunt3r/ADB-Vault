# Code of Conduct

ADB Vault welcomes contributors and users of all backgrounds and experience
levels. Help keep this project respectful, useful and safe to participate in.

## Scope

These rules apply to everyone, including maintainers, in this repository's
issues, pull requests, discussions and other project-managed community spaces.
They also apply when someone publicly represents the project.

## Expected behavior

- Be respectful and patient, especially with newcomers.
- Keep feedback constructive. Disagreement, criticism and bug reports are
  welcome; address ideas and behavior, not a person's worth or identity.
- Respect other people's boundaries, time and privacy.
- Take responsibility for mistakes and help resolve misunderstandings.

## Unacceptable behavior

- Harassment, discrimination, personal attacks, threats or intimidation.
- Sexual harassment or unwelcome sexual content and attention.
- Publishing someone else's private information without permission, including
  personal data in device logs, screenshots or backups.
- Spam, impersonation, deliberate disruption or repeated unwanted contact.
- Retaliation against someone who reports a concern in good faith.

## Reporting a concern

Use GitHub's **Report content** option on the relevant issue, pull request or
comment. If **Report to repository admins** is available, it sends the report to
the maintainers. **Report abuse to GitHub Support** sends it to GitHub instead.
GitHub also provides a contact form; see its
[reporting guide](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).

For a concern that is safe to discuss publicly, you may also mention
[@vaulthunt3r](https://github.com/vaulthunt3r) in the relevant thread with a brief
description and a link to the content. Do not post private evidence, personal
information or accusations that expose someone to further harassment in a
public issue. This project does not currently publish a separate private
moderation email address.

Security vulnerabilities should follow [SECURITY.md](SECURITY.md).

## Moderation

Maintainers will consider the context, severity and any repeated behavior.
They may request a correction, issue a warning, hide or remove content, lock a
discussion, or temporarily or permanently restrict participation. Serious
abuse may lead to immediate restrictions without a prior warning.

Reports should be handled with care, sharing sensitive details only as needed
to investigate or act. Maintainers should explain decisions where practical
without exposing private information. A directly involved maintainer should
ask another uninvolved maintainer to review when one is available.

You may request a review through the same reporting routes, providing relevant
context without restarting the dispute publicly. GitHub independently handles
reports submitted to GitHub Support under its own policies.
