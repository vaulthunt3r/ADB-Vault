# Проверка Wi-Fi ADB

Отдельный локальный сценарий для Windows. Не требует интернета, npm install или пересборки приложения. Использует ADB из настроек ADB Vault.

Запуск из корня проекта:

```powershell
node scripts/wifi-session-test.mjs
```

Введите текущий IP и **порт подключения**, указанные на главном экране «Беспроводная отладка», затем выполняйте подсказки. Можно передать адрес заранее:

```powershell
node scripts/wifi-session-test.mjs --target 192.168.1.134:40971
```

Адрес в примере может устареть. Дополнительный `--alias-prefix adb-HARDWARE_SERIAL-` учитывает mDNS-транспорт того же телефона; используйте только проверенный идентификатор.

Четыре блока: приложение закрыто/открыто × VPN выключен/включён. Каждый блок: 30 секунд с включённым экраном, 120 секунд с выключенным, 30 секунд после пробуждения. Поддерживайте экран включённым касаниями в соответствующих этапах. Перед каждым действием сценарий ждёт Enter. S пропускает блок; Q на вопросе или Ctrl+C завершает с частичным отчётом. Закрытие окна крестиком может не дать сохранить HTML; потоковый events.jsonl остаётся на диске.

Для второй половины сценарий после подтверждения запускает текущую уже собранную версию проекта через Electron. Оставьте её на Connection. Если окна нет, пропустите этап; это будет видно в отчёте. Тест не закрывает приложение автоматически. VPN и блокировка экрана переключаются пользователем. Перед каждым блоком сначала восстановите связь без VPN, затем включите VPN, если этого требует блок.

Сбор данных:

- `adb devices -l` примерно каждые 2 секунды, с ограничением времени каждого запроса;
- новые строки внутреннего журнала ADB, включая короткие разрывы;
- фактический маршрут Windows до IP и процессы приложения примерно каждые 10 секунд;
- однократная TCP-проба перед блоком с включённым экраном. Во время сна TCP-проб, ping и команд Android нет.

Сценарий не вызывает connect/disconnect/pair/kill-server и не меняет сетевые настройки. Сам ADB может автоматически восстанавливать ранее установленное соединение. Команда devices может запустить сервер ADB, если его нет.

Результаты: `desktop-test-results/wifi-session-<время>/report.html`, `events.jsonl`, `adb-events.log` (если были новые события). HTML содержит этапы, изменения состояния, события ADB, маршруты и процессы. Этапы экрана/VPN — отметки пользователя, не измерение состояния телефона. Глобальные сообщения TLS помечены отдельно: они могут относиться к другому подключённому устройству. Статус device не гарантирует непрерывность связи; проверяйте журнал. Причина обрывов автоматически не назначается.

Проверки сценария без изменения соединений:

```powershell
node scripts/wifi-session-test.test.mjs
node scripts/wifi-session-test.mjs --target 192.168.1.134:40971 --self-check
```
